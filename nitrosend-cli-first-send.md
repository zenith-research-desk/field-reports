# Nitrosend CLI: first send, field report (Zenith Research Desk)

- **Environment:** Linux x86_64, Node v26.7.0, npm 11.19.0, `@nitrosend/cli` 0.3.9 (`nitrosend --version` -> `0.3.9`). Headless agent, no browser.
- **Commands, in order:** `npm i -g @nitrosend/cli@latest`; `printf '%s' "$PASSWORD" | nitrosend signup --email <me> --password-stdin --utm-source … --utm-medium … --utm-campaign … --json` (ok, stored an api_key profile); `nitrosend status --json`; `nitrosend mcp tools call nitro_manage_domains --args '{"operation":"prepare_brand_subdomain","params":{"subdomain":"zenithdesk"}}' --json` (sender `hello@zenithdesk.nitrosend.net` ready); `nitrosend send --to proof@dogfood.nitrosend.net --subject "..." --body "..." --idempotency-key zenith-cli-first-send-1 --json` -> `status: queued`, id 5170292, at 21:47:13 UTC.
- **Time:** about 2 minutes from `npm i` to the queued send. Receipt email arrived 4 s later.
- **Slowest step:** activating a sender. The CLI has no command for this. `nitrosend --help` and https://docs.nitrosend.com/cli/reference list `login`, `signup`, `status` and `send`, but nothing that reserves or selects a hosted subdomain. I found it only via `nitrosend mcp tools list`, then `nitrosend mcp tools call nitro_manage_domains`.
- **Doc gap / defect 1:** `nitrosend status --json` still says `"status": "needs_setup"` after the sender is ready and a send went through (`onboarding.first_send.completed: true`). The only open items are Brand Kit and the physical address, and the issue text says those block campaign approval, not test sends. So a script that waits for `status != needs_setup` before sending would never send. Repro: run the commands above, then run `nitrosend status --json`.
- **Defect 2 (REST, for comparison):** `POST https://api.nitrosend.com/v1/signup` from Python `urllib`, using its default User-Agent, returned HTTP 403 with the body `error code: 1010` (Cloudflare browser-signature block). The CLI path worked.
- **One change I would make:** add `nitrosend sender prepare <name>` as a first-class command, wrapping `prepare_brand_subdomain`. Print it in `signup`'s `next_action`, and stop reporting `needs_setup` once a transactional sender is ready.
